# Axiom UI/UX 系统审计与重新设计决策

审计日期：2026-08-28

审计基线：`main@1edc568`（v0.8.2）

审计范围：React/Tauri 桌面端的导航、采集、页面处理、错题库、课程、今日学习、练习与批改、洞察、设置，以及共享 UI primitives。底层领域算法、SQLite schema、AI pipeline 和原生媒体能力仅用于理解任务，不因本次 UI 重设计而重写。

## 1. 审计方法与判断原则

本审计同时使用源码页面清单、领域模型、SQLite 数据生命周期、现有测试、当前设计文档、历史截图和 Vite 预览。点击成本按“用户可见的界面动作”计算；Finder、相机权限等系统界面单独计数。异步任务如果连续发生但共享一个明确进度界面，记为一次等待；后台任务不阻塞用户时不计等待。认知决策指用户必须比较选项、回忆上下文或判断下一步的次数，不包括机械点击。

重新设计的优先级固定为：熟悉 > 清楚 > 顺手 > 高效 > 稳定 > 精致 > 个性化 > 新颖。每项设计都必须减少记忆、跳转、误触或重复判断中的至少一项；“更现代”“更高级”不是有效理由。

## 2. 产品、对象与用户心理模型

Axiom 不是照片管理器，也不是 AI Dashboard。它是一个以“错题进入—理解—练习—反馈—再安排”为闭环的本地学习工作台。用户面对的核心对象及其关系如下：

| 对象 | 用户理解 | 主要生命周期 | 主要界面 |
| --- | --- | --- | --- |
| 采集页 / 原始文档 | 一张待拆分的试卷或错题图片 | 获取 → 校正 → 切题 → 已处理 | 采集、页面处理 |
| 错题 | 可搜索、可编辑、可练习的学习对象 | 已保存 → 已归档 / 回收站 → 恢复 | 错题库列表、错题详情 |
| AI 整理结果 | 题干、题型、解答、图形与标签的辅助结果 | 等待 → 处理中 → 完成 / 失败 / 取消 | 错题详情、状态提示 |
| 课程 / 教材 | 某科目正在使用的一套知识范围 | 导入 → 识别 → 结构确认 → 使用 / 删除 | 课程、教材导入 |
| 课程节点 / 标签 | 章节、知识点、方法、模型、错因 | 候选 → 待确认 → 可用 / 归档 | 知识结构、标签概览、审核确认 |
| 今日安排 | 当前最值得完成的一组学习主题 | 待学习 → 完成 / 延后 | 今日 |
| 练习与作答 | 固化题目、练习文档和一次提交 | 准备 → 作答 → 提交 → 批改 → 确认 | 练习、提交、结果 |
| 学习状态 / 洞察 | 从已确认证据推导的复习状态 | 变化、预测、可重建 | 今日、洞察、设置 |

界面必须使用这些用户对象，而不是 `ModelRun`、内部 ID、schema、排版引擎或数据库术语组织导航。

## 3. 用户角色与核心场景

### 3.1 主要角色

1. **学生（主要操作者）**：将纸面错题快速录入，理解解答，完成当天练习并订正。对 AI 与课程图谱的技术细节不敏感，最关心“下一步做什么”和“结果是否可信”。
2. **家长 / 家教（共同管理者）**：帮助导入教材、修正题目和标签、检查学习进度。需要更高的信息密度、可审计状态和可恢复操作，但仍不应接触内部实现术语。
3. **教师（次要但兼容的角色）**：批量整理题目、按课程结构审核标签、查看薄弱点。当前产品是单机 Beta，不为多人协作、权限或班级管理创建不存在的导航。

### 3.2 核心使用场景

- 学生刚做完作业，用 iPhone 连续拍摄或从 Finder 导入多页试卷，确认题块后保存。
- 学生打开应用，直接看到今天要学什么，生成练习、提交作答、确认批改并进入下一轮。
- 学生或家教按题干、科目、知识点和复习状态查找错题，查看解答、编辑信息、归档或恢复。
- 家教首次设置课程，导入教材，确认教材信息和目录结构，再审核 AI 提议的知识点与标签。
- 家长查看近 7 / 30 天学习趋势、掌握分布和需要关注的技能。
- 管理者配置 AI 服务、复习偏好、外观与更新；这些是低频维护任务，不得抢占学习主流程。

## 4. 现有信息架构与页面清单

当前一级导航是今日、采集、错题库、课程、洞察，设置位于侧栏底部；但应用实际默认打开采集，导航顺序与默认落点不一致。一级页面内部结构如下：

| 一级页面 | 当前二级结构 | 当前主要对象 | 审计结论 |
| --- | --- | --- | --- |
| 今日 | 今日主题、订正、未来任务量；进入练习后替换整个工作区 | 今日安排、练习 | 正确的首页候选；缺少真正的 First Use 下一步 |
| 采集 | 相机 / 导入模式；最新采集队列；进入页面处理 | 原始文档、题块 | 主流程可用，但共享控件和状态语义仍混杂 |
| 错题库 | 错题 / 已归档 / 回收站；筛选；列表与长详情 | 错题 | 主从结构正确；详情过长、操作层级与批量模式语义不稳定 |
| 课程 | 知识结构 / 标签概览 / 审核确认；教材导入独立流程 | 教材、节点、标签 | 层级较成熟；空态过大、复杂流程缺少稳定步骤导航 |
| 洞察 | 时间范围；趋势、掌握度、诊断、技能明细 | 聚合学习证据 | 信息丰富；需要统一表格、状态和窄窗降级 |
| 设置 | AI 服务、复习、外观、维护、关于、更新 | 偏好与维护 | 二级导航合理；Setting Row、Radio、Switch 语义尚未统一 |

## 5. 最高频核心任务与当前成本

记号：`C`=应用内点击，`N`=系统界面动作，`P`=工作区/页面层级变化，`W`=阻塞等待，`K`=确认，`D`=认知决策。数值为典型路径，不包含输入文本所需键击；“从任意其他模块开始”会额外增加一次一级导航点击。

| 核心任务 | 起点 → 终点 | 当前典型成本 | 当前成功状态 | 当前失败状态 |
| --- | --- | --- | --- | --- |
| 1. 导入并保存错题 | 采集 → 页面处理 → 已进入错题库队列 | `C3 + N1 + P1 + W2 + K1 + D5`：切换导入、选文件、保存题块；Finder 确认；导入/识别与保存 | Toast 表示保存成功，页面仍保留未保存题块，并提供前往错题库动作 | Toast 字符串；失败位置可能是导入、识别、刷新或保存，恢复入口不一致 |
| 2. 相机连续采集 | 采集 → 本地处理队列 | 首次 `C2 + N1 + W1 + D2`，后续每页 `C1 + W1` | 每页明确进入队列，可继续拍摄 | 权限、连接、方向、重新连接失败都通过 Toast；状态区域不统一 |
| 3. 完成今日练习与订正 | 今日 → 练习 → 提交 → 批改结果 → 今日 | `C4–7 + P3–5 + W2–4 + K1–2 + D4–8`，随打印/扫描/人工确认变化 | 学习证据写入，今日任务完成或进入下一轮 | 生成、提交匹配、提取、批改均可能失败；部分错误已有恢复页，整体位置感依赖页面标题 |
| 4. 查找并处理一道错题 | 错题库 → 列表筛选 → 详情 / 编辑 | `C2–5 + P0 + W1 + K0–1 + D3–6` | 详情与列表并存；编辑、归档、恢复后有反馈 | 详情长滚动导致功能难发现；批量模式改变行点击语义；软删除仍要求二次确认 |
| 5. 导入教材并确认课程结构 | 课程 → 教材导入 → 信息确认 → 结构确认 → 课程 | `C5–8 + N1 + P4 + W2–3 + K1–2 + D8–12` | 课程、章节、知识点和待审核标签可继续使用 | 失败可重试，但阶段、已保存内容和返回后位置不始终清楚 |
| 6. 查看学习洞察 | 洞察 → 时间范围 / 技能明细 | `C1–3 + P0 + W1 + K0 + D2–4` | 趋势、分布和技能表同页可扫描 | 空数据与读取错误的恢复动作不足；窄窗表格依赖横向滚动 |
| 7. 配置 AI 与复习偏好 | 设置 → 分类 → Setting / Provider | `C2–6 + P0 + W1–2 + K0–1 + D4–10` | 自动保存或明确保存成功；连接测试有结果 | 自动保存、手动保存和立即生效混合；互斥选择使用自造按钮式控件 |

## 6. 逐项 UX 问题分类

### 6.1 信息架构问题

- 默认落点是“采集”，而一级导航和产品闭环把“今日”放在首位；返回用户无法直接进入最高频任务，新用户也看不到完整学习路径。
- 错题详情把题目、标签、重复题、解答、复习历史、删除和变式串成一个超长页面，属于多个任务阶段被压在同一层级，而不是信息丰富。
- “错题 / 已归档 / 回收站”是同一对象集合的持久视图，当前用 Segmented Control，语义更接近 Tabs。
- 设置中的 AI 服务、复习偏好、外观、维护、关于、更新虽然已有二级导航，但内部页面仍各自发明 section / card / action bar。
- 课程的教材导入是复杂完整流程，已采用独立工作区是正确方向；但缺少稳定步骤指示，用户需要从文案推断所处阶段。
- 页面切换会卸载当前模块，搜索、选中对象、展开状态和正在进行的子任务可能丢失，破坏上下文连续性。

### 6.2 交互模型问题

- 错题列表在普通模式点击进入详情，在批量模式点击改为选择；同一对象、同一点击位置承担两种语义。
- 详情头部同时显示收藏、编辑、重新裁剪、归档等多个同权重操作；低频操作没有进入 More Menu。
- “移入回收站”是可恢复操作，却使用二次确认；更合适的模式是立即执行 + Toast 撤销。
- 页面处理中的删除采用按钮二次“武装”，既不是成熟确认 Dialog，也没有 Undo；用户需要学习专有状态。
- 相机“连续多页”是立即生效 Boolean，当前是无共享视觉的原生 checkbox；应使用 Switch。独立题块选择才应使用 Checkbox。
- 外观和颜色主题是互斥选择，却由按钮与手工 `role=radio` 模拟；应由统一 Radio Group / Choice Card 表达。
- 多个 back 图标方向和文案不稳定；进入完整子流程后都应使用“返回 + 上层对象”或 Breadcrumb。

### 6.3 组件一致性问题

- 仓库已有 Button、IconButton、Input、SearchField、Checkbox、ListboxSelect、Tabs、Dialog 等 primitive，但采集、页面处理、裁剪和部分详情仍使用 `primary-button`、`secondary-action`、`icon-button` 和原生控件预算例外。
- 同性质状态同时使用 status dot、pill、badge、纯文字、InlineNotice 和 Toast，视觉与 ARIA 行为不同。
- 缺少正式 Radio、Switch、Combobox、Breadcrumb、Navigation Item、List Row、Table、Tooltip、Popover、Sheet、Skeleton 和页面模板。
- `Surface` 容易被当作任意有边界容器；Card、Section、Inset Surface 的使用条件尚未通过类型和文档区分。

### 6.4 视觉层级问题

- 旧 `App.css`、共享 `ui.css` 与最后加载的 `uiRefinement.css` 形成三层覆盖；相似页面可能依靠选择器权重而非组件契约获得一致外观。
- 页面标题、Section 标题和内容标题虽有 Token，feature CSS 仍存在自定义字重、line-height 和局部层级。
- 当前课程空态被放进接近整屏的虚线容器，信息很少但占据主要视区；它传达的是“占位布局”而不是下一步任务。
- 详情页多个区块仍通过边框、浅色背景和圆角逐层包裹，内容层级依赖容器而非排版、间距与分组。

### 6.5 信息密度问题

- 错题列表行有标题、日期和两个状态，但缺少最影响选择的科目 / 关键知识点；用户常需打开详情才能确认。
- 错题详情同时显示所有低频历史与变式信息，导致高频题目和解答被长页面稀释。
- 课程空态、模块占位和部分 Loading 使用过高 `min-height`；在 820×620 窗口中会把下一段内容推离首屏。
- 洞察技能表信息密度合理，但窄窗只提供横向滚动，没有优先级降级。

### 6.6 可发现性问题

- 今日无安排时最显眼动作是“重新检查”，但首次使用真正下一步通常是“添加错题”；错误的 Primary Action 增加试错。
- 变式入口位于错题详情底部，用户必须滚过所有内容才能发现。
- 错题高级筛选使用原生 `details` 尚可，但激活的筛选数量与一键清除缺少明确反馈。
- 列表窄窗上下堆叠详情时，选择一题后详情可能出现在视口之外，用户看不到点击结果。

### 6.7 反馈问题

- 主要异步链路已有 Toast、Progress、FlowingTaskSurface 和 ErrorState，这是可保留基础；但同一错误有时只是一段字符串。
- Toast 会被后续 Toast 替换，长任务的持久状态必须留在页面或侧栏状态入口，不能只依赖瞬时通知。
- 某些按钮通过文字变成“正在…”但没有共享 loading indicator / `aria-busy`。
- 设置同时存在自动保存状态条、显式保存按钮和立即切换，用户难以预测“操作是否已经生效”。

### 6.8 错误预防与可恢复性问题

- 离开未保存设置已有全局 guard，是正确模式；但模块卸载仍会清除无需丢失的浏览上下文。
- 可恢复软删除仍被当成高风险不可逆操作确认；真正永久删除反而尚未成为明确独立流程。
- 页面处理删除、合并、拆分缺少一致 Undo 策略。
- 表单错误多为 Toast，字段本身没有总能收到 Inline error；验证失败时虽然大多保留值，但修复位置不够明确。

### 6.9 可访问性问题

- 共享 Tabs、ListboxSelect 和 Dialog 已有键盘与 focus 基础，应保留。
- Sidebar 选中项只有 class，没有 `aria-current="page"`；快捷键与窄窗 tooltip 未形成契约。
- 若干图标按钮依赖 `title`，共享 Tooltip 尚未定义；部分图标大小出现 17 / 21 / 22 等非系统值。
- 状态 dot 单独使用时可能只依赖颜色；所有状态必须同时有文字或屏幕阅读标签。
- 可点击 `div` / `article` 虽有部分 role 与键盘补丁，仍应优先使用语义 button / link。
- 对话框已有焦点环与焦点恢复，但 Sheet / Popover / Menu 的焦点策略尚未统一。

## 7. 目标信息架构

### 7.1 Primary Navigation

| 入口 | 责任 | 进入后的首要问题 |
| --- | --- | --- |
| 今日 | 今日安排、订正、生成/继续练习 | “我现在最应该完成什么？” |
| 采集 | 相机、图片导入、待处理页面 | “怎样把纸面内容加入 Axiom？” |
| 错题库 | 搜索、筛选、浏览和管理错题 | “我要找哪道题并做什么？” |
| 课程 | 教材、知识结构、标签与审核 | “当前学习范围和分类是否正确？” |
| 洞察 | 学习趋势、掌握度和诊断 | “最近发生了什么、下一步关注什么？” |
| 设置 | AI、复习偏好、外观、维护、关于与更新 | “怎样改变应用行为或维护状态？” |

应用默认进入“今日”。Primary Navigation 只切换模块，不直接执行操作。Sidebar 不增加与“采集”重复的全局添加按钮；用户在今日空态和错题库空态可通过明确动作进入采集。

### 7.2 Secondary / Contextual Navigation

| 所在页面 | 结构 | 控件 |
| --- | --- | --- |
| 错题库 | 错题、已归档、回收站 | Tabs |
| 错题详情 | 题目与解答、学习记录、变式题 | Tabs；保留所选错题上下文 |
| 课程 | 知识结构、标签概览、审核确认 | Tabs |
| 教材导入 | 选择资料、识别资料、确认信息、确认结构 | 独立页面 + Progress Steps + Back |
| 练习 | 题目页、答题页、解答页 | Segmented Control；这些是同一文档的互斥呈现 |
| 设置 | AI 服务、复习、外观、维护、关于、更新 | 垂直 Navigation / 窄窗水平 Tabs |
| 编辑器 / 裁剪 / 提交 / 结果 | 返回来源对象 | Breadcrumb 或带文字 Back |

### 7.3 Search、Filter 与 Actions

- Search 仅存在于可检索集合：错题、课程树、标签表；使用 SearchField。
- 状态 / 科目 / 难度等改变结果集合的是 Filter；短集合用 Select，已激活筛选可见且能一键清除。
- Global Actions 只包括跨页面仍合理的系统级行为；当前不创建冗余“全局添加”按钮。
- Contextual Primary Action 在 Page Header 或当前任务区最多一个，例如“生成今日练习”“导入教材”“保存 3 道错题”。
- 高频 Secondary Action 直接可见，例如编辑、重试、检查更新。
- 重新裁剪、归档、移入回收站、删除凭据等低频动作进入 More Menu 或设置行尾；Danger 保持红色语义。

### 7.4 内容与容器选择规则

| 任务 | 容器 | 理由 |
| --- | --- | --- |
| 教材导入、页面处理、练习与提交 | 独立页面 | 多阶段、信息量大、需要明确位置和返回路径 |
| 错题、课程节点浏览 | List / Master-Detail | 对象间连续浏览，切换对象时保留列表上下文 |
| 错题完整内容 | Detail Page / Detail Pane | 对象身份稳定，可分 Tabs / Sections |
| 简短解释、筛选辅助 | Popover | 短暂信息，无需离开上下文 |
| 新建少量标签、手动创建课程 | Dialog | 少量输入，完成后立即返回原任务 |
| 窄窗筛选或次级详情 | Sheet | 需要保留原页面，同时内容超过 Popover |
| 移除 API Key、删除课程 | Confirm Dialog | 会造成服务不可用或移除大量结构，风险较高 |
| 移入回收站、归档 | Inline / Menu + Undo Toast | 可恢复，不用打断任务 |
| Boolean 偏好 | Switch | 立即生效的二元状态 |
| 两到四个互斥模式 | Segmented Control / Radio Group | 模式可见且可比较 |

## 8. 目标任务流

### 8.1 添加错题

`今日空态 / Sidebar 采集 → 选择相机或导入 → 获取页面 → 自动进入页面处理 → 调整题块与收录选择 → 保存 N 道错题 → 保留当前页面并提供“前往错题库”`。

相机连续模式每页只执行拍摄，队列持续可见；结束时选择队列项进入处理。识别失败保留原图和用户调整，重试不重新选择文件。保存失败保留全部题块与选择。

### 8.2 今日练习与订正

`启动进入今日 → 优先显示待订正（若有）和今日主题 → 一个 Primary Action 生成/继续练习 → 练习文档 → 提交作答 → 批改结果 → 确认结果 → 返回今日或再练一组`。

任何长任务显示阶段、已保存状态与可离开说明。用户返回其他模块再回来时，练习与提交上下文保持。

### 8.3 查找与处理错题

`错题库 → 搜索/筛选 → 点击行始终打开详情 → 详情 Tabs → 编辑或学习`。批量选择通过 Checkbox 独立完成，不改变行点击。宽窗维持主从视图；窄窗选中后进入单独详情并显示“返回错题列表”。

### 8.4 管理课程

`课程 → 选择科目/教材 → 知识结构 / 标签 / 审核`。教材导入为 `选择资料 → 识别 → 确认教材信息 → 确认结构 → 返回课程`；每步显示当前进度、已保存内容、返回后去向。审核项保持候选证据和确认动作在同一行或详情中。

### 8.5 查看洞察

`洞察 → 选择 7 / 30 天 → 先读结论与需要关注项 → 再查看趋势 / 掌握分布 → 必要时展开技能明细`。宽窗表格保留全部列；窄窗优先显示技能、掌握度、到期和建议，其余元数据放入行详情。

### 8.6 设置与维护

`设置 → 分类 → Setting Row / Provider Detail → 即时生效或明确保存`。每个设置项只采用一种保存模型：Switch / Radio 立即生效并反馈；复合表单显式保存；Provider 自动保存必须持续显示状态且离开失败时保留输入。

## 9. 全局交互硬规则

1. 同一列表行的主点击始终进入/切换该对象详情；Checkbox 只负责多选。
2. 每个局部任务区最多一个明显 Primary Action；多个并列按钮不得都使用 accent。
3. 可恢复动作优先 Undo，不显示确认；不可逆、高影响动作才使用 Confirm Dialog。
4. Switch 只表示立即生效 Boolean；互斥选择使用 Radio / Segmented Control；独立多选使用 Checkbox。
5. 从较大集合中选择单项使用 Select；需要输入筛选的较大集合使用 Combobox。
6. SearchField 必须使用 `type=search`、可理解 label，并支持清空。
7. 图标按钮只用于返回、关闭、搜索、刷新、更多、收藏、旋转等成熟图标；其余动作保留文字。
8. More Menu 只承载低频次要动作；当前任务的 Primary 与高频 Secondary 必须可见。
9. 所有异步动作必须在触发控件、局部状态区或持久任务入口中提供反馈；Toast 只作为补充。
10. 导航保持模块实例，返回时恢复搜索、选择、滚动和子任务状态；未保存修改继续受离开 guard 保护。
11. `Cmd+1…5` 可切换一级模块，`Cmd+,` 打开设置；快捷键始终有可点击替代。
12. 统一文案使用“今日、采集、错题、课程、教材、知识点、标签、练习、订正、洞察、AI 服务”，不在同一概念上交替使用 Today、资料库、题库等近义词。

## 10. 页面模板

| 模板 | 稳定骨架 | 当前适用页面 |
| --- | --- | --- |
| List Page | Page Header → View Tabs → Toolbar / Search / Filters → Count → List / Table → Loading / Empty / Error | 错题库、标签概览、审核确认 |
| Master-Detail Page | List Page 左侧 + Detail Header → Actions → Tabs → Content；窄窗为列表或详情 | 错题库、课程知识结构 |
| Detail Page | Back / Breadcrumb → Object Header → Primary / More → Metadata → Tabs / Sections → Content | 错题窄窗详情、练习结果 |
| Editor Page | Back → Title / Status → Secondary + 单一 Save → Main Canvas / Form → Inspector | 页面处理、重新裁剪 |
| Workflow Page | Back → Page Header → Progress Steps → 当前步骤内容 → 固定上一步 / 下一步 | 教材导入、作答提交 |
| Today Page | Page Header / 单一 CTA → 待订正 → 今日主题列表 → 次级预测 | 今日 |

| Settings Page | Page Header → Settings Navigation → Section Header → Setting Rows / Form → Inline Status | 设置 |

## 11. 状态设计矩阵

| 页面 / 对象 | Loading | Empty / First Use | Error / Partial | Success / Ongoing |
| --- | --- | --- | --- | --- |
| 今日 | Skeleton / “正在准备” | 原因 + “添加错题” Primary + “设置课程” Secondary | 保留已有计划，说明哪部分未刷新并提供重试 | 今日进度、待订正、生成/继续练习 |
| 采集 | 相机连接 / 导入按钮 loading | 说明两种来源；队列使用紧凑空态 | 权限、设备、文件、持久化分开说明 | 队列行和 Toast；连续采集不打断 |
| 页面处理 | 阶段状态 + canvas overlay | 未检测题块时提供手动新增 | 保留原图、题块与选择；允许重试 | 保存数量明确，下一步可见 |
| 错题库 | List skeleton，详情独立 loading | 无数据与无搜索结果使用不同文案和动作 | 列表/详情局部错误，不清除筛选 | 保存、编辑、归档、删除均反馈；删除可撤销 |
| 课程 | selector / tree skeleton | 导入教材或手动创建 | 允许 Partial Data；失败阶段可恢复 | 当前教材、待确认计数、后台任务入口 |
| 洞察 | Summary / chart skeleton | 说明需要先完成练习 | 某区失败不隐藏其他区 | 时间范围和数据时间明确 |
| 设置 | 控件 disabled + loading | 无 Provider 时新建入口 | 字段 inline error + 页面状态；输入保留 | 明确“已保存 / 立即生效” |

控件统一考虑 Default、Hover、Pressed、Focused、Selected、Disabled 和 Loading。状态不得只依赖颜色；图标、文字或形状至少提供一种冗余信号。

## 12. 响应式与窗口行为

Axiom 的产品边界是 macOS 桌面窗口，最低支持 820×620，不把桌面界面假装成移动网页。

| 宽度 | 导航 | 内容布局 | 操作降级 |
| --- | --- | --- | --- |
| ≥1440 宽屏 | 220–226px Sidebar | 内容最大宽度受模板约束，Master-Detail 可扩展 | Metadata 完整显示 |
| 1024–1439 普通桌面 | 200–220px Sidebar | 标准双栏 / 主从 | 次要 metadata 可换行 |
| 820–1023 窄窗口 | 176–188px Sidebar 或稳定窄栏 | Master-Detail 变为列表或详情；设置导航变横向；采集上下分区 | 低频操作进入 More；详情显示显式 Back |
| <820 | 非正式支持 | 不承诺完整业务布局；不得作为本次“移动端”设计依据 | 应保持可恢复，不允许核心按钮不可达 |

所有页面只有一个主滚动所有者。固定高度工作区只允许 canvas、列表或详情区域拥有明确独立滚动；禁止 padded page scroller 内再放 `100vh` 子页面。

## 13. 实施前自我审计与优先级

设计不是从颜色或卡片开始。实施顺序固定为：

1. 扩充语义 Token 与共享组件，建立 Page Template 和自动审查规则。
2. 修复 App Shell：今日默认入口、Sidebar 语义、快捷键、模块 keep-alive 和窄窗导航契约。
3. 迁移采集与页面处理到共享控件和 Editor / Workflow 模板。
4. 重构错题库交互：Tabs、稳定行点击、独立 Checkbox、详情 Tabs、More Menu、Undo、窄窗主从切换。
5. 为课程导入增加步骤导航，收敛空态、列表、表格和 Dialog。
6. 收敛 Today、Insights 与 Settings 的模板、Radio / Switch / Setting Row 和状态表达。
7. 删除无引用 legacy 规则，运行代码、UI contract、键盘、主题和 820×620 / 普通 / 宽屏视觉检查。

实施前方案逐项检查结果：

| 维度 | 决策是否降低认知负担或提高效率 |
| --- | --- |
| Navigation | 默认进入今日；模块 keep-alive，返回不丢上下文 |
| IA | 长详情分 Tabs；复杂流程独立页面并显示步骤 |
| Interaction | 行点击稳定；批量选择独立；低频操作进 More |
| Error prevention | 高风险才确认；软删除提供 Undo；表单保留输入 |
| Hierarchy | 一个局部 Primary；主要依靠排版、间距、对齐和分组 |
| Density | 列表显示决策所需 metadata；低频历史进入次级 Tab |
| Accessibility | 语义控件、ARIA、focus、键盘和非颜色状态冗余 |
| Responsive | 窄窗主从切换而非无意义纵向堆叠 |

以上决策满足“熟悉、清楚、顺手、高效、稳定”后才允许处理精致度；不增加渐变、Glow、Glassmorphism、大圆角或装饰性 Dashboard 卡片。
