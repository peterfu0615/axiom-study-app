## 2. 一页结论

Axiom 已经从“把照片存起来的错题本”演进为一个本地优先的学习工作台。它目前具备一条较完整的学习闭环：

    采集题目 → 页面校正与 OCR → 人工确认题块 → AI 理解题目
        → 生成解答、识别作答和错因 → 绑定教材与知识标签
        → 进入错题库和今日复习 → 生成练习或变式题
        → 导出/打印练习 → 扫描作答 → 提取与批改
        → 用户确认批改结果 → 更新知识掌握度和复习计划
        → 在洞察页查看遗忘、重错、迁移和方法薄弱点

当前最成熟的部分是本地数据基础设施、媒体处理、AI 异步任务恢复、教材/标签约束、复习状态记录、练习文档和批改证据。代码已经考虑了迁移校验、事务原子性、重复提交、进程重启、失败恢复、原图不可变、危险 TikZ 拦截和 API Key 脱敏等真实桌面应用问题。

当前最值得投入的部分不是再添加一个孤立的 AI 按钮，而是把已有能力变成更可信、更容易理解、更可持续使用的产品：

- 把现有的教材解析、标签映射、复习、练习和洞察连接得更清楚，让用户知道“为什么今天推荐这道题”以及“这次批改怎样影响了后续计划”；
- 把已经存在于数据库和领域层的计划器、考试、作业、可用时间和统一调度器做成实际的用户界面；
- 解决 Provider 能力路由、教材多候选消歧、AI 失败解释、模型质量评估和隐私策略；
- 完善数据备份/导出、签名更新、公证发布和跨架构分发；
- 在稳定的本地闭环之上，再考虑语义检索、可选云同步、家教/教师协作和移动端伴随体验。

产品方向可以概括为：用户掌握最终判断权，AI 负责识别、整理、生成候选和提供解释；每个会改变学习状态的动作都应当有来源、证据、可追溯记录和恢复路径。

## 3. 软件当前介绍

### 3.1 产品定位

Axiom 面向中文 K12 学生，也适合家教和教师在单机环境中使用。它把题目图片、教材结构、知识标签、解题过程、学生作答、复习计划和练习批改放进同一套本地数据模型中。核心价值不是“替用户做一次题”，而是把一次错误转化为可复习、可验证、可再次练习和可长期统计的学习证据。

它具有三个同时成立的产品特征：

| 特征 | 当前含义 |
| --- | --- |
| 本地优先 | 图片、题目、教材、复习记录、练习作答和模型运行记录默认保存在本机 SQLite 与应用数据目录；不依赖 Axiom 自有服务端 |
| AI 辅助而非无条件自动化 | AI 输出经过 schema 解析、领域校验、受控映射或用户确认；批改结果在写入学习状态前需要满足证据条件或用户确认 |
| 学习闭环 | 错题不会停留在“看过解答”的状态，而是可以进入计划、练习、复测、掌握度更新和洞察 |

### 3.2 主要使用场景

| 使用者 | 典型任务 | Axiom 当前提供的支持 |
| --- | --- | --- |
| 学生 | 拍下作业或试卷中的错题，理解错误并重新练习 | 连续相机/导入、OCR、题块编辑、AI 解题、作答识别、错因分析、今日复习、变式练习、扫描批改 |
| 学生 | 按教材和知识点整理错题 | 教材导入、章节树、知识节点、知识/方法/模型/错误标签、标签审核和题目筛选 |
| 学生 | 判断自己是否真的掌握了某个知识点 | 复习评分、技能状态、掌握度、稳定性、可提取性、不确定性、迁移分数、变式题证据 |
| 家教/教师 | 检查学生集中出现的错误类型 | 错题库筛选、学生作答和推理详情、方法/模型诊断、标签审核、批量重标注 |
| 家教/教师 | 准备针对性练习 | 按复习单元和薄弱技能生成练习集，支持原题、变式题、答案页和解答页 |
| 未来协作者 | 管理作业、考试和可用学习时间 | 数据库已经有 planner 和统一 scheduler 基础，但当前还没有完整的计划器工作台 |

当前软件仍然是单机单用户产品。家教/教师场景主要体现为“同一台 Mac 上帮助一个学生整理和分析”，不是多账号、多人协作或班级管理系统。

### 3.3 用户主流程

#### 采集和整理

用户可以通过 macOS 相机、iPhone/Continuity Camera 或图片文件导入题目。系统把原图复制进应用数据目录，计算内容哈希并记录来源，不直接覆盖原图。文档处理会尝试检测页面边界、校正透视、增强图像、识别文字和推断题目块。用户可以在编辑器中移动、拆分、合并、删除、重命名题块，并补充答案区或图形区。

#### 理解和解答

题目保存后可以进入异步 AI Pipeline。模型可以返回题目标题、学科、题干、选项、子问题、知识点、方法、模型、错误类型、难度和提示。成功的题目分析会进一步排队生成标准解答；如果题目包含学生作答，还可以排队识别作答内容和分析第一处错误、错误原因、知识缺口与改进建议。

#### 教材和知识结构

用户可以导入 PDF、JPG、PNG 或 WebP 教材源文件。系统先在本地抽取页文本或执行 Vision OCR，再进行目录和知识点结构识别。用户可以确认教材元数据、编辑章节层级、审核候选标签、合并或归档知识节点，并将题目绑定到教材和受控标签。教材导入是带 checkpoint、阶段状态、失败页记录和恢复能力的长任务。

#### 复习和练习

已保存、已有受控标签并符合复习条件的题目进入今日计划。用户可以查看当天的复习单元、替换单元、延后单元、未来 7/14/30 天负荷预测，并直接为某个技能生成快速练习、标准练习或模拟测试。练习可以包含原题，也可以包含经过生成和验证的变式题。

#### 批改和学习状态回写

练习文档可以生成 PDF、打开、保存或打印。提交作答时，用户可以导入多页 PDF/JPG/PNG/HEIC，或使用连续相机扫描。页面身份和答案区域可以通过二维码、页面布局和图像分析恢复。系统支持选择题、判断题、数值、表达式、主观题 AI 批改和人工确认。只有最终批改结果完整、没有待确认项或已经经过用户确认，才会把证据写入复习状态。

### 4.1 采集、媒体和页面识别

采集层把“获取一张图片”和“把图片变成可编辑题目”分成两个阶段。Rust 端负责文件类型、大小、目录和安全路径约束，媒体被放进 app_data_dir 下的 original、corrected、problems、diagrams、textbooks 等受控子目录。原图和后续裁剪结果是不同文件，SQLite 只记录路径、哈希、来源和结构化状态。

macOS 原生侧车 AxiomVision.swift 使用 AVFoundation、Vision、Core Image、PDFKit 和 ImageIO。它负责相机方向观察、页面分割、透视校正、图像增强、OCR、PDF 页面文本或图像提取。题块坐标使用左上角为原点的 0–1 归一化矩形，因此窗口大小、缩放和不同预览尺寸不会改变领域数据。

这套设计为未来增加扫描仪、批量文件夹监听、手写识别或其他 OCR 引擎保留了边界：新增来源只需要产生受控的原始媒体和标准化的文档/区域结果，不应直接修改 React 内部状态或绕过数据库。

### 4.2 错题库

错题库已经不只是列表页。用户可以在 active、archived 和 trash 之间切换，按文字、科目、难度、教材、章节、知识点、方法、模型和复习状态筛选；全文检索通过 SQLite FTS5 和触发器保持题干、解答、标签、笔记等搜索源同步。

详情页可以展示题图、题干、选项、子问题、标准解答、学生作答、推理分析、模型运行、原始输出、错误、图形区域、生成图形和复习历史。用户可以编辑题目标题、科目和文本，调整裁剪，收藏、记笔记，归档、恢复、软删除，处理重复题，并对同一科目题目批量重标注或迁移教材。

回收站保留结构化数据和媒体引用，媒体清理由显式的目录枚举和删除命令完成。未来如果增加永久删除、数据导出或备份，必须延续“先确认引用关系，再处理媒体”的原则。

### 4.3 AI Provider 和异步流水线

当前 Provider 抽象支持三种主要来源：

- Mock Provider：用于开发、测试和没有外部模型时的流程验证；
- OpenAI Compatible：通过 Rust 请求兼容 Chat Completions 的端点，支持端点拼接模式、结构化输出降级、SSE 流式响应和本地图片路径；
- Antigravity CLI：通过本机命令、模型参数、JSON 输出和 JSON Schema 运行本地 CLI，并限制命令路径、超时、输出大小和图片路径范围。

题目分析、解答、作答识别、推理分析、教材识别、教材阶段分析、几何场景、主观题批改、变式生成和变式验证都经过统一的 Provider 接口。提示词、JSON Schema、解析器、repair strategy 和领域对象分开维护，模型返回不会直接变成 UI 状态。

AI Pipeline 的共同结构是：

1. 从 model_runs 或对应任务表领取一个待处理任务；
2. 装载题目、图片、教材匹配和受控上下文；
3. 按能力选择 Provider，记录每次尝试和运行版本；
4. 请求模型，保留安全的原始输出、使用量、响应时间和错误；
5. 解析 JSON、执行 schema/领域校验，必要时进行受限修复；
6. 在事务中写入分析结果、标签映射和完成状态；
7. 为解答、作答、推理或几何图形建立后续任务；
8. 进程重启时继续未完成任务，终态任务不会被重复领取。

前端当前的 AI 错误模型已经定义了 AUTHENTICATION_ERROR、NETWORK_ERROR、TIMEOUT_ERROR、RATE_LIMIT_ERROR、PROVIDER_ERROR、MODEL_CAPABILITY_ERROR、REQUEST_INVALID、MODEL_OUTPUT_ERROR、SCHEMA_VALIDATION_ERROR、MAPPING_ERROR、PERSISTENCE_ERROR 和 CANCELLED 等分类。Rust 端还会对 Provider 返回进行脱敏，避免 API Key 出现在日志或错误详情中。下一步需要把这些分类完整投射到用户界面，而不是只显示一段字符串。

### 4.4 Horizon 教材和知识系统

Horizon 的核心不是一个静态的“标签下拉框”，而是一套带来源、生命周期和审核状态的知识数据模型：

| 对象 | 作用 |
| --- | --- |
| textbook / textbook_page | 记录教材身份、科目、年级、版本、页和证据 |
| knowledge_node | 表示书、章、节、知识点、定义、公式、定理或性质 |
| knowledge_edge | 表示包含、前置、推导、相似、易混、使用和出现关系 |
| tag_definition | 将知识、方法、模型、错误类型定义为可审核的受控标签 |
| tag_alias | 保存同义词、教材别名和模型输出的可匹配词 |
| problem_tag | 保存题目与标签的映射状态、来源、置信度、锁定和用户验证 |
| curriculum_import_job / attempts | 保存教材导入的阶段、checkpoint、重试和运行凭证 |

教材解析先做本地抽取和结构化，再由 AI 补充候选结构、标签和审计。用户可以确认、拒绝、归档、合并和批量审核。题目分析在完成前可以根据科目解析有效教材，并把选定教材的知识上下文限制在候选知识节点和 active 标签范围内；写入时会保留 unresolved 或 needs_review 状态，而不是把未知文本伪装成已绑定标签。

当前 UI 以章节树和标签审核为主，知识边已经有持久化模型和关系类型，但尚未发展成可交互的图谱视图，也没有成熟的自动关系推断。它是未来做教材内检索、先修关系、相似题迁移和错因传播分析的基础。

### 4.5 今日复习、练习和洞察

复习系统已经具备独立的会话、模块、问题实例、技能状态和复习日志。记录结果时会在同一事务中写入 review_attempts、技能状态、技能 bundle 状态、tag evidence、Horizon review log 和会话完成状态，并通过 result_key 做幂等保护。复习状态带有 scheduler version，未来更换算法时可以迁移或重放，而不是覆盖历史记录。

练习系统把“选哪些题”和“如何生成文档”分开。planner 根据 mastery band、失败次数、目标标签、题目相似度、难度和数量预算建立 practice blueprint；生成的 practice set 固化题目快照，避免源题后续编辑导致历史练习改变。变式题有单独的生成计划、模型运行和验证结果，验证失败时回退原题并记录原因。

练习批改不直接把模型一句“正确”写成掌握证据。系统保存答案提取、标准答案、批改运行、修订链、有效答案链、用户覆盖和每个标签的证据；存在待确认或低置信度结果时，会阻止最终应用学习状态。这是当前架构中非常重要的可信边界。

洞察页目前可以查看复习完成情况、趋势、掌握分布、未来到期/逾期技能、重错率、稳定性、迁移分数、原题和变式证据，以及方法和模型诊断。它已经是实际工作区，不再只是数据库预留。

## 5. 技术实现总览

### 5.1 分层结构

当前代码的主要依赖方向如下：

    features → domain
    features → platform ports
    platform → Tauri / WebKit / SQLite
    Rust commands → app data directory / native sidecars
    ai → domain contracts + platform provider wrappers

| 层 | 主要职责 | 约束 |
| --- | --- | --- |
| React features | 采集、错题库、课程、今日、练习、洞察、设置等用户工作流 | 不直接实现底层文件和模型供应商协议 |
| domain | 领域类型、选择算法、复习算法、练习规划、批改规则、几何验证、状态迁移 | 不导入 React、Tauri 或供应商 SDK，可在纯测试中验证 |
| platform | SQLite 查询、事务辅助、Tauri IPC wrapper、媒体 URL、学习状态持久化、恢复和维护 | 负责把外部副作用映射成领域可理解的数据 |
| ai | Provider 抽象、提示词、schema、解析、错误分类、任务 pipeline | 模型输出必须先经过版本化契约和领域校验 |
| Rust/Tauri | 单连接 SQLite、文件复制/哈希、Vision/Typst 调用、PDF、图形渲染、更新、密钥读取 | 受控命令边界，不把任意路径或任意命令暴露给前端 |
| Swift/Typst sidecar | macOS Vision/PDF/相机能力和离线文档渲染 | 作为可检查、可签名的外部二进制，不能绕过应用数据目录策略 |

### 5.2 启动、数据库和恢复

应用启动时先通过 Rust 初始化 app_data_dir 下的 SQLite，并在前端校验 tauri-plugin-sql 与 Rust sqlx 是否解析到同一物理文件。路径不一致时，应用显示 DatabaseLocationErrorDialog，阻止后续 AI 和数据操作；修复命令只复制数据库，不自动删除源文件，也不会覆盖已存在的目标。

SQLite 使用 WAL、外键、busy timeout 和单一 sqlx 连接加 Mutex。前端数据库 wrapper 通过 db_select/db_execute 等命令访问同一连接，避免多连接池在 BEGIN/COMMIT 之间交错。Release 构建关闭高成本 SQL trace；日志目录显式位于应用数据目录下的 logs/axiom.log。

启动后会按顺序执行复习调度器迁移、Provider 配置、问题分析恢复、解答恢复、智能分析恢复和几何场景恢复。更新检查在后台静默执行；网络失败不阻塞主工作区。

### 5.3 数据生命周期

媒体生命周期是：

    用户授权或选择
      → Rust 校验扩展名、大小和来源
      → 复制到 app_data_dir 并计算 SHA-256
      → 原图、校正图、题图、图形图和教材源文件分层保存
      → SQLite 保存引用和结构化结果
      → 归档/回收站保留引用
      → 显式媒体清理处理无引用文件

数据生命周期是：

    source_documents
      → problems / problem_regions / user_edits
      → model_runs / provider_attempts / raw output / usage
      → problem_solutions / student_attempts / reasoning_analyses
      → textbooks / knowledge_nodes / tag_definitions / problem_tags
      → review_sessions / skill_states / review_attempts / tag_evidences
      → practice_sets / practice_items / attempts / grading / loops
      → insights / forecasts / scheduler audit

其中模型运行、复习和批改证据尽量采用追加记录或不可变快照。可变的当前状态用于快速读取，历史记录和版本字段用于重建、审计和迁移。

### 5.4 AI 请求和凭据边界

当前持久化 API Key 的事实源是 SQLite 的 ai_provider_profiles.api_key。Keychain 仅用于旧版本数据的一次性恢复，不是新版本的主要存储位置。前端只接收是否存在、末尾少量字符等安全状态，AI 请求时由 Rust 在数据库内部读取密钥；Provider 错误消息会做替换和脱敏。

OpenAI Compatible 请求会对 URL 模式和网络协议进行校验。默认要求 HTTPS，本机回环地址可用于本地服务；端点可以按 api_root、v1_base 或 full_endpoint 解释。结构化输出会根据 Provider 能力在 json_schema、json_object 或 prompt_only 之间降级，并把探测结果记录到 ai_provider_capabilities。

这套边界减少了前端泄漏密钥的风险，但 SQLite 本身仍是本地明文数据库意义上的持久化存储。未来若面向更广泛发行，建议把系统 Keychain 提升为新数据的主存储，并让 SQLite 只保留凭据引用和元数据。

### 5.5 图形、数学和练习文档

几何图形不是直接把模型生成的任意 TeX 交给渲染器。GeometryScene 先验证实体 ID、引用关系、证据来源、置信度和约束；GeometryTikz 再把通过验证的场景编译到很小的安全 TikZ 子集，拒绝宏、循环、文件访问等能力。渲染结果保存校验信息和契约版本，失败时保留原图。

练习文档使用 Rust 生成 PDF，并使用固定版本 Typst 侧车处理需要排版的内容。数学文本经过受限转换，未知或危险的 LaTeX/Typst 命令会失败而不是直接泄漏到输出。页身份二维码和答案区域让纸质作答能够在多页、旋转和部分 OCR 失败的情况下恢复。

### 5.6 macOS 构建和发布

Tauri 配置要求 macOS 13 或更高版本，bundle 中包含 axiom-vision 和 axiom-typst 两个 externalBin。Cargo build.rs 会编译 Swift Vision 侧车并暂存固定版本 Typst。发布脚本会分别为侧车和主 App 处理 entitlements 与 codesign，工作流支持 Developer ID 签名、公证和未签名 Beta 三种路径。

CI/release 会通过 uname -m 检测 arm64 或 x86_64，并要求相应的 Vision 二进制存在。当前仓库可见的是 aarch64 侧车，因此实际可复现的主线构建重点仍是 Apple Silicon；Intel 构建流程是预留能力，不代表当前已经具备完整 Intel 发布物。

自动更新读取 GitHub Release Atom feed，选择与当前架构匹配的 .app.zip，下载进度、读取 .sha256、校验后解压，并由 detached 脚本等待旧进程退出、替换 App、移除 quarantine 和重启。当前校验是完整性校验，不是 Tauri updater 式的签名验证；如果更新源、传输链路或同一发布渠道被攻破，SHA-256 文件本身不能提供独立信任根。

## 6. 数据库和迁移演进

数据库迁移采用只追加、不复用版本号、不修改已发布迁移文件的规则。Rust 启动阶段使用嵌入式迁移列表执行，tauri-plugin-sql 不注册迁移。0024–0026 等历史迁移包含显式事务，执行器只在运行时剥离最外层事务边界，磁盘原文和 SHA-384 checksum 保持不变。

迁移可以按产品能力分为以下阶段：

| 迁移 | 能力族 | 主要数据 |
| --- | --- | --- |
| 0001–0015 | 基础题库与初代 AI | source documents、problems、用户编辑、初代 AI 字段、provider profiles、解答、学生作答、provider attempts、旧 credential_ref |
| 0016–0023 | Horizon 和教材关联 | taxonomy、textbooks、pages、knowledge nodes/edges、tag definitions/aliases、problem tags、导入任务、教材匹配 |
| 0024–0029 | 历史数据修复和恢复 | 扁平化教材树、重标注 claim、审核约束、学习循环基础、同级唯一性、失败教材页 |
| 0030–0038 | AI 可靠性、今日引擎和图形基础 | 结构化 AI 错误、教材解析审计、今日完整性、复习索引、科目身份、图形渲染 |
| 0039–0048 | 练习系统 | 练习域、练习文档、文档身份、作答、练习循环、统一文档、验证图形、批改修订、有效答案链、变式题 |
| 0049–0051 | 复习和批改生命周期 | review session 事件、批改证据、复习偏好、应用状态 |

| 0056–0058 | 计划器和统一调度 | 学习容量、可用时间、考试、作业任务、计划分段、统一调度迁移审计 |

迁移完整性测试覆盖新库从头升级到 0059、旧库从 0027 等历史版本升级、重复或乱序版本、约束和追加日志。迁移版本本身是产品兼容性的一部分，未来不能因为“表结构看起来可以简化”而直接删除或改写历史 SQL。

## 7. 当前审查结论：强项、边界和技术债

### 7.1 已经形成的强项

#### 本地数据基础设施强

单连接 SQLite、WAL、外键、路径一致性检查、显式迁移、事务边界、幂等结果键、历史重放和失败恢复，说明代码已经针对桌面端最常见的数据损坏和重复执行问题做过工程化处理。这个基础足以承载下一阶段的计划器、检索和更多学习状态，而不需要先重写存储层。

#### AI 已经进入可恢复的任务系统

AI 不再只是一个同步按钮。每个任务有状态、运行记录、Provider 尝试、错误、原始输出、使用量和后续任务；应用重启时可以继续执行。后续应继续加强策略和可观察性，不需要推倒重建整个 AI 层。

#### 学习证据链比普通题库完整

从原题、教材标签、复习结果、练习作答、批改修订到 skill state，系统能够区分原题证据、变式证据、用户确认和模型置信度。这使“掌握了”不再只由一次模型判断决定，也为未来的学习分析和教师解释提供了数据基础。

#### 安全边界意识较明确

本地 API Key 不穿过前端 IPC、路径和媒体目录受控、Provider 错误脱敏、图形渲染使用安全子集、主观批改需要确认、更新脚本不直接覆盖用户数据库。这些机制不代表风险已经消失，但说明扩展时有可延续的约束。

### 7.2 当前仍然存在的边界

| 优先级 | 现状 | 影响 | 建议 |
| --- | --- | --- | --- |
| P0 发布信任 | 自动更新只做 SHA-256，主线仍允许未签名 Beta | 用户无法获得独立的发布者身份保证，存在供应链和渠道风险 | 迁移到签名更新或为 Release 资产建立独立签名验证；完成 Developer ID、公证和 staple |
| P0 AI 诊断 | 错误分类和安全错误 envelope 已有，但部分 UI 仍偏向显示普通字符串；测试中还有 mock 未提供 claimNextStudentAttemptModelRun 的 stderr 警告 | 用户难以判断应重试、改密钥、换模型还是修正题目；测试信号会掩盖真正问题 | 完成错误状态组件、操作建议和 mock 契约清理；按错误类别测试重试/切换规则 |
| P1 Provider 路由 | 0052、domain/provider selector 和测试保留了 task_types 路由；当前工作区 AISettings 的保存逻辑又有把 Provider 统一视为启用/文本可用并清空 taskTypes 的迹象 | 多 Provider 时无法稳定表达“视觉任务用哪个、解答任务用哪个”，配置模型和 UI 语义不一致 | 统一配置真相源，明确空 taskTypes 是“全部任务”还是“无任务”，增加能力探测和任务级路由界面 |
| P1 教材歧义 | 有确定性候选筛选、AI resolver、回退策略和审计，但多个教材候选时仍可能落到“最新 active 教材”的稳定回退 | 错题可能被绑定到错误教材，后续标签和复习推荐会连锁偏移 | 在题目分析前显示候选教材和依据；无法安全判断时进入 unresolved，不应静默猜测 |
| P1 计划器产品面 | 0056–0058 已有考试、作业、可用时间、容量、任务和统一调度表，但 Sidebar/App 当前没有计划器工作区 | 用户不能把真实考试和作业约束提供给调度器，今日页只能表达复习负荷 | 先做计划器最小 UI，再把 review/correction/homework/exam_prep 统一到每日任务 |
| P1 数据可携带性 | 当前有迁移维护和媒体清理，但尚未形成面向用户的全量备份、恢复、导出和跨机器搬迁流程 | 本地优先产品在换机、重装或误操作时缺少可理解的恢复路径 | 增加加密备份包、校验、恢复预览、JSON/CSV/PDF 导出；明确媒体、数据库和迁移版本关系 |
| P1 质量评估 | schema、解析器和结构校验较多，但还没有可持续的模型质量基准、回归数据集和任务级准确率面板 | 供应商或提示词变化可能改变解题、标签、批改质量，却不容易在发布前发现 | 建立脱敏 golden set、离线评测、领域指标和提示词/模型版本对比 |
| P2 知识图谱 UI | knowledge_edges 已持久化，关系类型丰富，但主要 UI 仍以树和标签审核为主 | 无法直观看到先修关系、易混关系和知识网络，图谱价值没有完全转化为学习行为 | 增加图谱局部视图、边证据、合并/冲突处理和由图谱驱动的检索 |
| P2 检索能力 | 题库已有 FTS5 trigram 和结构化筛选，尚无混合语义检索或本地向量索引 | 同义表达、跨题型迁移和图像相似题发现能力有限 | 先做词法+标签+教材章节混合检索，再按隐私选择本地或可选 embedding |
| P2 数学正确性 | 变式生成和 TikZ 有结构验证，解答和批改仍主要依赖模型与规则组合 | 结构合法不等于数学证明正确，错误答案可能影响学习状态 | 引入数值/符号检查、答案一致性、步骤约束和人类确认，不把 LLM 单独视为证明器 |
| P2 文档一致性 | README 和部分历史报告仍停留在旧版本/旧功能描述 | 新开发者会误判当前能力和缺口，发布沟通成本高 | 以本文为总览，随后同步 README、CHANGELOG、Release Checklist 和文档索引 |
| P2 真实设备覆盖 | 纯逻辑和模拟原生测试充分，连续相机、不同纸张、实际 Provider、Gatekeeper 流程仍需要真实设备 Acceptance Test | 设备权限、相机曝光、PDF 版式和模型网络问题可能只在实机出现 | 建立固定实机回归清单和脱敏样例，不用单元测试替代验收 |

### 7.3 “已实现”不等于“已产品化”的功能

以下能力在代码中已经有较多基础，但用户还不能把它们当作完整产品承诺：

- planner 的数据表和调度器已经存在，但没有计划器工作区、考试输入和任务解释；
- knowledge edge 已有关系类型和数据库约束，但没有面向学习的图谱导航和关系审核体验；
- Provider task routing 已有迁移、类型、选择器和测试，但设置界面语义仍不统一；
- 自动更新有下载、哈希校验和替换脚本，但没有独立签名信任；
- AI 错误有机器码，但部分失败路径还没有把“下一步怎么办”变成 UI 操作；
- 变式题有生成和验证流程，但“验证通过”目前主要代表契约和结构检查，需要更强的数学与事实一致性；
- 复习算法有版本和回放能力，但真实长期数据量还不足以证明各个阈值对不同年龄和学科都合适。

## 8. 未来可拓展功能与方向

未来方向应当围绕已有数据资产展开，而不是创建彼此独立的新模块。下面按产品价值和技术依赖说明扩展路径。

### 8.1 学习计划器：从“今日复习”扩展到“整周学习安排”

数据库已经提供 planner_preferences、planner_availability、planner_exams、planner_tasks、planner_schedule_runs 和 planner_task_segments。下一步可以把它们变成用户看得见的计划：

- 输入考试日期、作业截止时间、每天可用时间、科目优先级和复习保留时间；
- 将复习、错因纠正、练习、作业和考试准备统一为任务；
- 允许任务拆分、锁定、延后、跳过和重新排程；
- 将今日页从“当前到期内容列表”升级为“按可用时间安排后的行动清单”；
- 对每个计划给出原因，例如“由于数学函数知识点将在两天后低于目标保持率，所以安排 20 分钟变式练习”；
- 记录计划版本、输入 hash 和用户改动，支持解释“为什么这次计划和上次不同”。

实现顺序应是先做只读计划预览，再做可编辑任务，最后接入真实日历或系统通知。不能先把自动排程做成不可解释的黑盒。

### 8.2 Horizon 知识图谱：从树状目录扩展到可用知识网络

教材章节树适合浏览，但不够表达“先学什么、哪些概念容易混淆、一道题同时使用哪些方法”。可以在现有 knowledge_edges 上增加：

- 关系的来源页、证据文本、置信度和审核状态；
- 局部图谱视图，而不是一次显示整个大图；
- 知识点合并、拆分、重定向和冲突检查；
- 根据题目标签自动提示先修知识、相似知识和易混知识；
- 把错误类型连接到知识节点和方法节点，形成“错误 → 缺口 → 推荐复习”的链路；
- 用图谱关系构建练习 bundle，保证一组题覆盖同一核心技能的不同表现。

图谱关系不能完全依赖模型猜测。每一条影响复习或标签的边都应保存来源、生成版本和审核状态，自动关系只能作为 candidate。

### 8.3 混合检索：从关键词查题扩展到“找相似学习证据”

当前 FTS5、标签、教材、章节和字段筛选已经足够支撑第一版题库。扩展时建议采用分层检索：

1. 先用 subject、textbook、chapter、active tags 做硬过滤；
2. 再用 FTS5 对题干、解答、笔记和错误描述做词法匹配；
3. 再可选地使用本地 embedding 或用户明确授权的远程 embedding 做语义排序；
4. 最后结合难度、复习状态、相似题去重和证据质量重新排序。

这样可以让“检索相似题”与“推荐下一道题”使用不同的策略。向量索引不能取代受控知识映射，也不应在没有隐私提示的情况下把全部本地题目上传到外部服务。

### 8.4 AI Provider 平台：从“能调用”扩展到“可治理”

Provider 数量增加后，核心问题会从请求协议转向治理。可以增加：

- 按任务和模型能力的显式路由：视觉分析、解答、教材、批改、变式验证各有优先级；
- 自动能力探测：图片输入、JSON Schema、流式响应、最大上下文、速率限制；
- 按任务设置隐私等级：原图允许上传、仅上传裁剪图、仅发送 OCR 文本、完全离线；
- 按任务设置成本、延迟和失败切换预算；
- 按错误类别做重试：网络/限流可重试，鉴权/请求格式错误不应无意义切换；
- Provider 健康度和最近能力测试结果；
- 模型运行成本、token、耗时和成功率的聚合；
- 一键导出脱敏诊断包，让用户能够报告问题而不暴露题目或密钥。

这一方向应先统一 profile、taskTypes、supportsVision/supportsText、endpoint capability 和 UI 保存语义，再增加更多模型供应商。

### 8.5 可信 AI 与评测：从 schema 合法扩展到结果可用

需要把“JSON 合法”“结构符合契约”和“教育内容正确”区分开。建议建立脱敏、可版本化的评测集，覆盖：

- 中文印刷题、手写作答、低光照片、倾斜页面、多栏试卷；
- 选择题、多小题、含公式题、图形题、跨页题；
- 教材目录和知识点识别；
- 标准解答的答案一致性和步骤完整性；
- 学生作答第一错步识别；
- 变式题的知识目标保持、难度变化和答案验证；
- 选择/数值/表达式/主观题批改的一致性。

每次更新提示词、schema、解析器、模型或 Provider 都应该输出版本对比。发布门槛至少包含解析成功率、受控标签命中率、批改待确认率、错误分类准确性和回归样例差异。

### 8.6 练习系统：从“生成一套题”扩展到“针对性纠错”

在现有 practice blueprint、variant plan、grading evidence 和 practice loop 之上，可以增加：

- 根据第一处错步生成针对同一误解的最小练习；
- 分开检测“会做原题”和“能迁移到不同表述”；
- 根据独立完成、提示使用、耗时和订正次数调节证据权重；
- 为家教/教师提供题量、难度、知识覆盖和排除条件；
- 生成分层练习：基础恢复、同型巩固、跨情境迁移、综合题；
- 把错误订正自动变成下一轮练习，但允许用户取消；
- 为每个变式题提供“保留了什么、改变了什么、如何验证”的说明。

变式生成仍应坚持“生成候选 → 独立验证 → 用户可见来源 → 最终进入学习证据”的流程，不能把未经验证的生成题直接用于掌握度更新。

### 8.7 数据可携带性和恢复

本地优先产品必须把“本地”与“只有一份数据”区分开。建议提供：

- 一键创建加密备份包，包含 SQLite、媒体、教材源文件、版本信息和迁移状态；
- 恢复前显示包内版本、大小、题目数、教材数和冲突预览；
- 仅导出题库的 JSON/CSV/Markdown/PDF；
- 按科目、教材或时间段导出图片和解答；
- 从备份恢复到新设备时保留原始 ID、媒体哈希、模型运行和学习状态；
- 删除数据前展示外部引用关系，并提供可恢复的回收站期限。

恢复流程必须复用现有迁移和路径校验，不应通过复制一个未经检查的数据库文件来绕过 schema 保护。

### 8.8 隐私、离线和本地模型

可以增加一个清晰的隐私策略面板，把每类数据的处理方式展示出来：

| 数据 | 默认处理 | 可扩展选项 |
| --- | --- | --- |
| 原始照片 | 本地保存 | 仅上传裁剪区、处理后自动删除外部副本 |
| OCR 文本 | 本地保存并可发送给文字模型 | 仅本地模型、发送前编辑 |
| 教材 | 本地抽取和索引 | 仅发送当前页/当前片段，不上传整本 |
| API Key | 当前由 SQLite 保存 | 新版本迁移到系统 Keychain |
| 练习作答 | 本地保存 | 外部批改前逐次确认 |

本地模型可以先从 OCR、文本分类、答案等价性和 embedding 开始，而不是一开始就要求本地运行大型视觉模型。这样能降低硬件要求，并保留“无网络也能完成部分学习工作”的价值。

### 8.9 分发和平台扩展

产品成熟后可按以下顺序扩展：

1. Apple Developer ID 签名、公证、staple 和签名更新；
2. 补齐 x86_64 Vision/Typst 侧车，或明确只支持 Apple Silicon；
3. 增加崩溃诊断、版本兼容和可撤销的更新策略；
4. 把核心领域模型和数据导出格式稳定下来；
5. 在数据协议成熟后再考虑 iPad/iPhone 采集端、Web 查看端或可选云同步；
6. 最后再引入多用户、教师班级和协作权限。

移动端和云同步都不是简单地“把 React 再编译一次”。它们需要解决媒体同步、离线冲突、模型运行归属、隐私授权、学习状态合并和版本迁移。因此应以后端无关的数据协议和事件/快照语义稳定为前置条件。

## 9. 建议的分阶段实现路线

下面是一条按依赖关系排列的路线。时间可以根据团队规模调整；比固定日期更重要的是每阶段的退出条件。

### M0：基线和发布卫生

目标是让团队对“当前有什么”和“当前能不能发布”达成同一认识。

实现顺序：

1. 将本文设置为项目总览入口，更新 README 的版本、迁移范围和功能清单；
2. 建立 docs index，明确哪些文档是当前规范、哪些是历史报告；
3. 清理测试中未提供真实依赖的 mock，至少消除 Pipeline 运行时 stderr 警告；
4. 记录一次可复现的前端、Rust、原生侧车和发布产物检查；
5. 为 SQLite、媒体、AI 配置和模型运行建立最小诊断信息，不包含题目内容和密钥；
6. 明确当前发布架构边界：Apple Silicon 可发布，Intel 是待补侧车的构建目标。

退出条件：

- 新开发者只读 README、本文件和文档索引即可知道现状；
- npm run lint、npm run typecheck、npm test、Rust fmt/clippy/test 通过且无已知 mock 噪声；
- Release Checklist 能区分“代码检查通过”“未签名 Beta”“签名公证 Stable”；
- 版本号、迁移最高版本和发布资产命名一致。

### M1：可靠性、诊断和信任

目标是让已有闭环在失败时可解释、可恢复，且用户可以信任下载和本地数据。

实现顺序：

1. 将 AIErrorEnvelope 投射到统一 ErrorState：错误标题、原因、是否可重试、下一步操作、safe detail；
2. 根据错误类别实现 retry/fallback policy，鉴权和请求格式错误不盲目重试；
3. 完成 Provider 任务路由模型：Profile、能力探测、taskTypes、默认顺序和 UI 保存语义只保留一套真相；
4. 教材分析前展示候选教材、选择依据和 unresolved 状态，禁止无提示的高风险猜测；
5. 添加本地加密备份/恢复的最小版本，恢复前执行 schema、媒体引用和版本校验；
6. 将 API Key 新存储迁移到 Keychain，SQLite 只保留引用和非敏感配置；
7. 为更新包增加发布者签名验证，随后启用 Developer ID、公证和 staple。

退出条件：

- 401、429、超时、模型不支持图片、JSON 无效、schema 失败、映射失败、数据库失败在 UI 和 ModelRun 中可区分；
- 多 Provider 场景能说明本次用了谁、为什么切换、是否产生费用；
- 多教材场景不会静默绑定到不确定教材；
- 用户可以在新 Mac 上验证备份并恢复题目、媒体、教材和学习状态；
- Stable 更新不再依赖同一渠道提供的裸 SHA-256 文件作为唯一信任。

### M2：计划器和统一学习行动

目标是把今日复习从一个到期列表升级为可执行的学习计划。

实现顺序：

1. 新增 PlannerWorkspace，先展示考试、作业、可用时间、容量和计划预览；
2. 把 review、correction、homework、exam_prep 统一成可解释任务；
3. 把 TodayWorkspace 的复习单元与 planner task segment 关联；
4. 支持用户锁定、延后、拆分、跳过和重新计划；
5. 让预测图同时展示学习负荷、考试截止时间和目标保持率；
6. 将计划变更写入不可变 schedule run 和事件表；
7. 在设置中暴露目标保持率、每日容量和复习保留时间，并给出影响说明。

退出条件：

- 用户可以输入一次考试和一次作业，系统生成可查看、可修改、可回溯的两周计划；
- 每个自动安排的任务都能解释来源、优先级和预计时长；
- 今日完成、延后或替换会改变后续计划，但不会重复计算同一学习证据；
- 计划器失败或重启不会丢失用户已锁定的任务。

### M3：知识图谱和混合检索

目标是让教材和标签真正参与“找题、推荐题、解释错因”。

实现顺序：

1. 设计 graph slice API，只查询当前知识点的局部节点和边；
2. 在课程页增加局部图谱、边证据和关系审核；
3. 建立教材章节/知识点/别名/题目标签的混合检索；
4. 将先修、易混和相似关系接入题目详情和今日推荐解释；
5. 把“知识缺口 → 相关原题 → 变式题 → 下一次复习”的链路呈现出来；
6. 评估本地 embedding，先支持索引重建和删除，再决定是否支持远程服务；
7. 增加标签合并、重定向和图谱变更的审计回放。

退出条件：

- 用户可以从一个知识点找到教材证据、相关错题、相似题和待复习任务；
- 每条影响推荐的关系都有来源或明确标注为候选；
- 词法、标签、章节和语义检索可以解释排序原因；
- 删除或合并标签后，历史复习证据仍然可追溯。

### M4：高质量针对性练习

目标是把练习从“选一些题”提升到“针对某种错误设计最小纠正路径”。

实现顺序：

1. 将 reasoning analysis 的第一错步和知识缺口转为 practice target；
2. 为同一 target 生成基础、同型、迁移、综合四类练习；
3. 为变式题加入答案一致性、数值验证、符号检查和步骤约束；
4. 让批改结果区分独立完成、使用提示、修改后正确和用户覆盖；
5. 将待确认批改显示为明确的人工任务，而不是静默阻塞；
6. 提供家教/教师的题量、难度、知识覆盖和排除项；
7. 建立练习质量评测集和真实用户反馈入口。

退出条件：

- 一次错误能够生成一套有明确目标、来源和验证说明的练习；
- 未通过验证的变式题不会进入最终学习证据；
- 批改不确定时，用户能在不丢失原始作答的情况下修订并重新批改；
- 完成练习后，用户能看到哪些证据改变了掌握度和下一次复习时间。

### M5：生态、协作和平台扩展

目标是在本地单用户体验稳定之后，逐步扩大设备和协作范围。

候选工作：

- macOS 签名、公证、稳定自动更新、Intel 或 Universal 构建；
- 本地导出格式和备份包的跨版本兼容；
- iPhone/iPad 作为采集端，Mac 作为本地分析端；
- 可选云端同步，但保留离线工作和用户主动授权；
- 家教/教师班级、批注、作业布置和学生权限；
- 对外开放稳定的数据导入/导出和插件接口。

退出条件不是“多了一个客户端”，而是：

- 同一题目、媒体、模型运行、批改证据和学习状态在设备间有稳定身份；
- 冲突处理有明确规则，不能因同步覆盖用户确认或历史证据；
- 用户能逐项查看和撤销外部同步授权；
- 教师权限不会绕过学生数据隐私和批改确认边界。

## 10. 建议的工程拆分

为避免大范围重写，后续工作可以拆成以下相互独立、可回滚的纵向切片：

| 切片 | 前端 | 领域/数据 | Rust/平台 | 验证 |
| --- | --- | --- | --- | --- |
| AI 错误状态 | ErrorState、重试/换 Provider/查看安全详情 | AIErrorEnvelope 到 UI action 映射 | 保持脱敏和错误码 | 错误矩阵、Pipeline 回归 |
| Provider 路由 | Profile 编辑、能力测试、任务路由 | route policy、capability cache | endpoint/response format 探测 | 多 Provider 模拟、迁移测试 |
| 教材消歧 | 候选教材卡片、用户确认、unresolved 状态 | resolver decision、confidence、audit | 可选保留现有 resolver | 单教材/多教材/无教材 |
| 备份恢复 | 创建、预览、恢复、冲突提示 | backup manifest、版本和 hash | 原子复制、路径校验、加密 | 换目录、损坏包、旧版本 |
| Planner 工作台 | 考试、作业、容量、计划预览 | planner schema 与 review task 关联 | 复用现有调度表 | 完成/延后/重启/重复任务 |
| 图谱视图 | 局部图、边审核、来源页 | graph slice、candidate edge | 查询和索引优化 | 边合并、归档、回放 |
| 混合检索 | 搜索解释、相似题入口 | lexical/tag/semantic ranking | 可选本地索引 | 删除、重建、排序回归 |
| 练习质量 | 目标选择、批改确认、解释 | evidence weight、variant contract | 数值/符号辅助验证 | golden set、人工抽检 |
| 更新信任 | 签名状态、失败操作 | release metadata | 签名校验、公证、回滚 | 离线、坏包、旧包、重启 |

每个切片应尽量同时包含数据迁移、domain contract、platform implementation、UI、单元测试和一条真实验收路径。不要先把大量字段加入数据库，再等待很久才决定它们如何呈现给用户。

## 11. 长期设计原则和暂不建议做的事

### 应持续坚持的原则

1. 原图、原始作答、原始模型输出、历史批改和复习事件尽量不可变；当前状态可以重建。
2. AI 输出先通过版本化 schema，再进入领域规则和用户界面。
3. 任何影响掌握度、标签或复习时间的自动动作都要能说明来源、证据和算法版本。
4. 失败应当有明确状态和恢复入口，不能用空数组或“已完成”隐藏失败。
5. 本地数据和外部 AI 上传必须分开描述、分开授权、分开记录。
6. 迁移只追加，真实用户数据库视为不可逆资产。
7. 领域算法尽量保持纯函数和可回放，避免把学习状态逻辑散落在 React 组件中。
8. 新功能优先复用已有问题、标签、证据和任务模型，避免建立第二套平行学习状态。

### 暂不建议优先做的事

- 在 Provider 路由、错误诊断和备份恢复未稳定前继续堆叠更多模型供应商；
- 在受控标签和混合检索基础未稳定前直接上向量数据库；
- 在本地学习状态和事件语义未固定前做云同步；
- 在变式验证和批改证据不足时宣传“完全自动批改”或“保证解答正确”；
- 在完成 Planner 最小闭环前做复杂的日历、通知和全自动时间管理；
- 在真实设备 Acceptance Test 不足时先做大范围 UI 重写；
- 为了简化代码而修改 0024–0026、0027 等已发布迁移或删除历史字段。

## 12. 建议的最终验收标准

### 用户闭环

- 用户能从一张照片或导入文件得到可编辑题块；
- 用户能明确知道题目是否已保存、AI 是否成功、失败为什么失败；
- 用户能看到解答、自己的作答、第一处错误和知识缺口；
- 用户能从题目进入今日复习或针对性练习；
- 用户完成练习后能看到批改证据，并确认或修正结果；
- 用户能看到学习状态变化和下一次行动，而不是只看到一次性的分数。

### 数据和恢复

- 应用重启不会重复领取或丢失未完成 AI/教材/批改任务；
- 同一结果重复提交不会重复增加学习证据；
- 迁移失败会保留旧数据并给出可恢复提示；
- 原图和用户确认过的历史结果不会被后台处理覆盖；
- 用户可以备份、恢复、导出和删除自己的数据。

### AI 和隐私

- 每次 AI 运行能记录 Provider、模型、契约版本、耗时、使用量和安全错误；
- API Key 不出现在前端状态、日志和错误详情；
- 上传图片前有清晰的 Provider/数据范围提示；
- 结构化输出失败、模型能力不足和数学内容不确定不会伪装成成功；
- 需要用户确认的标签、批改和教材匹配不会自动写成最终事实。

### 发布和质量

- 当前版本号、迁移版本、README、Release 资产和更新页一致；
- Apple Silicon 构建可复现，其他架构要么有对应侧车，要么明确不支持；
- Stable 构建完成签名、公证、验证和更新回滚测试；
- 前端、Rust、迁移、原生侧车和真实设备 Acceptance Test 都有记录；
- 更新失败、网络不可用和安装中断不会删除用户数据。

## 14. 总结

Axiom 当前已经拥有较少见的完整基础：它把图像采集、OCR、AI 解答、教材知识结构、错因分析、间隔复习、变式练习、纸笔扫描和学习洞察放进了同一套本地数据和任务系统中。下一阶段的核心不是证明“还能再调用一个模型”，而是让已有系统在真实学习中更稳定、更透明、更可恢复。

推荐的总路线是：

    先统一基线和发布信任
      → 再完善 AI 诊断、Provider 路由、教材消歧和备份
      → 再把 planner 和统一 scheduler 做成用户工作区
      → 再用 Horizon 图谱和混合检索提升推荐质量
      → 再强化变式练习、数学验证和批改证据
      → 最后扩展到签名分发、跨设备和可选协作

如果按此顺序推进，Axiom 会从“功能很多的 Beta 工具”逐步变成“可以长期托管学生学习证据的个人学习系统”。这条路线既利用了当前已经投入的大量数据和领域代码，也把最可能导致数据错误、用户不信任或未来返工的风险放在了前面。
